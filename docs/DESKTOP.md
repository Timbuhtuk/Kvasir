# Пульт Kvasir на WPF

`Kvasir.Desktop` использует .NET 10 WPF и [Tessera.WpfStyles 0.3.0](https://www.nuget.org/packages/Tessera.WpfStyles/0.3.0). Стартовая тема — тёмная, Light и Contrast переключаются в настройках. Копия пакета из NuGet.org хранится в репозитории. Лицензии MIT, Cascadia Code и Science Gothic включаются в публикацию.

## Запуск

Соберите всё решение, чтобы рядом существовала актуальная сборка бота:

```powershell
dotnet build Kvasir.sln -c Release -m:1 -p:UseSharedCompilation=false
dotnet run --project src/Kvasir.Desktop/Kvasir.Desktop.csproj -c Release --no-build
```

Запустите `Kvasir.Desktop.exe`: бот находится в `bot/Kvasir.exe`. При сборке решения MSBuild автоматически готовит эту папку рядом с WPF, поиск исходников во время запуска не используется. Папка данных определяется стандартным API Windows: `%LOCALAPPDATA%\Kvasir`. Одинаковый файл используется из Visual Studio и распакованного релиза.

Шестерёнка слева от сворачивания открывает отдельное окно настроек. В нём находятся переключатель темы, полный путь к конфигурации и кнопки открытия файла и папки данных. Иконка хранится отдельным SVG-файлом и отображается как вектор. Тема сохраняется в `desktop-settings.json` и восстанавливается при запуске.

При первом запуске приложение создаёт папку и копирует безопасный шаблон в `%LOCALAPPDATA%\Kvasir\configuration.json`. Один раз сохраните Discord-токен в первом элементе массива `tokens`:

```json
"tokens": ["YOUR_DISCORD_BOT_TOKEN"]
```

При отсутствии токена пульт сразу открывает отдельное окно ввода с защищённым полем. «Сохранить и запустить» сохраняет первый элемент tokens в конфигурации AppData и запускает бота; остальные параметры файла сохраняются. После этого повторный ввод не нужен. Заменить токен можно в настройках. При отказе Discord (401 / 4004) открывается специальное окно замены с объяснением причины. Бот читает файл при каждом запуске; токен не передаётся аргументами или через окружение. Значение хранится в памяти пульта для маскирования stdout/stderr. Журнал пульта содержит последние 500 строк с метками OUT/ERR. Очистка журнала пульта не удаляет журналы бота.

В новом публичном комплекте токен отсутствует: его нужно один раз добавить в свой локальный файл. Существующий файл в AppData не заменяется при первом запуске, пересборке или обновлении. При переходе со старой версии перенесите свою конфигурацию и относительную SQLite-базу/настройки серверов в папку AppData, сохраняя относительные подпапки. Абсолютные пути музыки из конфигурации продолжают использоваться. Также поддерживается строковый ключ `KVASIR_DISCORD_TOKEN` в JSON. Массив `tokens` имеет приоритет. Если токен отсутствует, дочерний процесс запускается только после успешного сохранения токена; окно ввода можно отменить. При прямом запуске бота без токена он выводит короткое сообщение и завершает работу с кодом 2. Переменная окружения остаётся дополнительным источником для консольного запуска, пульт использует файл.

## Управление

Кнопки запуска и остановки бота, статус и сообщения находятся в заголовке окна. После подключения нажмите «+» в строке вкладок и откройте нужные серверы. Повторный выбор уже открытого сервера переключает его вкладку. Закрытие вкладки не останавливает музыку. Каждая вкладка хранит последний снимок сервера, выбранный канал, раздел, плейлист, выделенный трек и черновики полей. При переключении состояние запрашивается заново. Очередь и воспроизведение остаются в сервисах бота; вкладки содержат только представление данных. Действие сохраняет адресата до отправки, поэтому переключение вкладки не меняет сервер выполняемой команды.

Голосовой канал выбирается справа в заголовке окна. Серверы и каналы показывают только названия. При активном голосовом соединении команды относятся к каналу бота. Запросы добавляются в настоящую `MusicQueue`, одинаковые песни в ней имеют независимые ID заказов. Правый клик по треку открывает меню строки. В нём можно поставить трек следующим, переместить выше или ниже, удалить его или отменить последнее добавление пульта. Стоп очищает очередь; отключение дополнительно закрывает голосовое соединение.

Плеер постоянно виден внизу. Основные действия представлены отдельными SVG-иконками с подсказками и именами доступности: пауза/продолжение, следующий трек, переключение повтора (выключен / трек / очередь). Кнопка «Перемешать очередь» находится слева от повтора. Громкость и позиция применяются после отпускания ползунка или клавиши; отдельные кнопки применения убраны. Остановка с очисткой и выход из канала находятся в меню «…». Время отображается в минутах и секундах. История показывает последние 50 треков сервера в текущем запуске.

В библиотеке доступны все плейлисты сервера, видимые администратору, и все треки выбранного плейлиста. Можно создавать личные/общие подборки, переименовывать, переключать доступ, удалять с подтверждением, менять порядок/удалять треки, добавлять текущий трек, отправлять в очередь подборку или отдельный трек. Импорт использует `MusicClientService.StartImport` и показывает прогресс и неудачные записи. Успешная часть импорта сохраняется при частичном сбое.

Раздел «Правила» сохраняет роль DJ, голосование, чередование заказчиков и лимит 1–1000. Поле ID роли скрыто в дополнительном раскрывающемся блоке. Локальный оператор управляет ботом как администратор, а не имитирует участника голосового канала. Его заказы и новые плейлисты принадлежат Discord ID бота. Права и ограничения участников в Discord не меняются. Черновик правил не перезаписывается обновлениями и восстанавливается при возвращении во вкладку.

Диагностика вызывает существующий IMusicDiagnostics и проверку кэша; дополнительно отображается голосовое соединение выбранного сервера. Очистка и восстановление вызывают IMediaCache, сохраняющий открытые файлы и защищающий внешние пути. На восстановление отведено до трёх минут.

Журнал открывается отдельным окном по иконке рядом с выбором голосового канала. Для ошибок авторизации, конфигурации, выбора канала, прав Discord, аудиокомпонентов, источника, сети, SQLite, доступа к файлам и частичного импорта предусмотрены отдельные сообщения с причиной и конкретным следующим шагом. Переход к настройкам, каналу или сервису предлагается там, где он доступен. Отказ авторизации сразу открывает защищённый ввод нового токена. Неизвестный сбой показывает краткую исходную причину, журнал содержит подробный контекст. Строки стека одного сбоя не создают серию одинаковых окон. Штатная остановка не считается ошибкой. Список сценариев и границы проверки описаны в [отчёте проверки](DESKTOP-VALIDATION.md).

Метаданные YouTube и аудио получает включённый в комплект yt-dlp без автоматического использования cookies браузера. Метаданные ограничены 50 секундами, скачивание — 90 секундами; для FFmpeg установлен отдельный предел в пять минут. Нативные загрузчики не наследуют управляющий stdin бота. FFmpeg определяет реальный контейнер WebM/M4A/MP3 и преобразует его в нормализованный PCM. Тайм-аут источника, ограничение площадки и зависание преобразования имеют разные сообщения.

## Связь и завершение

Пульт управляет только дочерним процессом, который запустил сам. Произвольный уже запущенный бот автоматически не подключается. Случайные имя именованного канала и ключ сеанса передаются через `KVASIR_CONTROL_PIPE` / `KVASIR_CONTROL_SESSION`. Оба конца требуют текущего пользователя Windows (`CurrentUserOnly`); сервер проверяет ключ на каждом запросе. TCP-порт не открывается. DTO/кодирование находятся в Kvasir.Control; данные EF и секреты в протокол не включены. Максимальный кадр — 8 МиБ. Обновление состояния — раз в две секунды и после действий, запросы последовательны; во время длительного действия кнопки блокируются. Команда после потери ответа автоматически не повторяется: перед ручным повтором проверьте состояние.

Закрытие окна/кнопка остановки отправляют `stop` через stdin. Закрытие stdin при завершении родительского процесса тоже запрашивает остановку бота. Пульт ждёт 40 секунд, затем оставляет окно открытым, если процесс ещё работает. Он не убивает бот, аудио и импорт завершаются его сервисами; на остановку Host отведено до пяти минут. При сообщении о тайм-ауте дождитесь завершения и повторите остановку/закрытие.

## Проверки этой миграции

Проверены компиляция решения с предупреждениями как ошибками и self-contained публикация для win-x64. Изолированные проверки: 165 в Kvasir.Tests (включая настоящий FFmpeg) и 88 в Kvasir.Desktop.Tests; WPF-набор добавлен в CI. Отдельный нативный media-probe прошёл 3 проверки метаданных, скачивания и PCM. Через computer-use проверены сохранённый токен, реальные серверы/каналы, воспроизведение, пауза, перемотка, повтор, громкость, пропуск, библиотека/импорт, история, вкладки, правила, диагностика, журнал и штатная остановка. Пользователь подтвердил нормальный звук в Konoha → «ремонт бота». Найденные ошибки, исправления и точные границы живого прогона перечислены в DESKTOP-VALIDATION.md.
